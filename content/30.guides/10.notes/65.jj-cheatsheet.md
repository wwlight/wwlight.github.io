::tip
与 Git 协作时

- 书签推送到远程后即为普通 Git 分支，同事可继续使用 `git commit`、`git switch`、`git pull`。
- 已执行 `jj git init` 的同一工作区中，日常操作使用 jj，避免混用 `git switch`、`git commit`。jj 没有「当前分支」，执行 jj 命令后 Git 常处于 detached HEAD。
- `.jj/` 不必提交。`jj git init` 会生成 `.jj/.gitignore`（内容为 `/*`），Git 会自动忽略它。
::

## 和 Git 命令对照

| 项 | 说明 |
| --- | --- |
| `@` | 当前工作区提交 |
| `@-` | 父提交 |
| 暂存区 | 无。修改文件后由下一次 jj 命令自动记录到 `@`，无需 `git add` |
| change ID | `jj log` 中较短的标识，改写提交后保持不变 |
| commit ID | 改写提交后会变化 |

```sh {1,5,7,9,10}
$ jj st                                                 # 相当于 git status
$ jj log                                                # 相当于 git log
$ jj diff                                               # 相当于 git diff（相对父提交）
$ jj describe -m "message"                              # 为当前提交添加说明
$ jj commit -m "message"                                # 添加说明并新建空工作区提交（缩写 ci）
$ jj squash                                             # 相当于 git commit --amend
$ jj new main                                           # 相当于切换到 main 并新建提交
$ jj bookmark list                                      # 相当于 git branch
$ jj git fetch && jj rebase -o main                     # 相当于 git pull --rebase
$ jj git push -b my-feature                             # 相当于 git push -u origin my-feature
$ jj undo                                               # 撤销上一次 jj 操作
$ jj restore <file>                                     # 相当于 git restore
```

## 配置

```sh {1,4,5}
$ jj config list                                        # 查看当前生效的配置
$ jj config list --user                                 # 查看用户级配置
$ jj config list --repo                                 # 查看仓库级配置
$ jj config set --user user.name "name"                 # 设置用户名
$ jj config set --user user.email "example@example.com" # 设置邮箱
$ jj config edit --user                                 # 编辑用户配置
$ jj config edit --repo                                 # 编辑仓库配置
$ jj config unset --user user.name                      # 删除用户级配置
```

## 初始化与克隆

```sh {1,4}
$ jj git init                                           # 初始化当前目录；已有 git 仓库则复用 .git
$ jj git init --colocate                                # 强制与 git 共用工作区
$ jj git init --git-repo=<git-path> <jj-path>           # 新增工作区，共享已有 git 仓库
$ jj git clone <url>                                    # 克隆远程仓库（默认与 git 共用工作区）
$ jj git clone <url> <dir>                              # 克隆到指定目录
$ jj git clone -b main <url>                            # 只抓取指定分支
```

## 日常流程

基于主干开始新工作并推送：

```sh {1,3,4}
$ jj new main                                           # 基于 main 新建工作区提交
$ jj commit -m "feat: add notes"                        # 添加说明并新建空工作区提交
$ jj bookmark create my-feature -r @-                   # 在父提交上创建书签
$ jj git push -b my-feature                             # 推送指定书签；未跟踪时自动跟踪
```

拉取远程并变基到主干：

```sh {1,2}
$ jj git fetch                                          # 从远程抓取更新
$ jj rebase -o main                                     # 将当前历史变基到 main 之上
```

## 状态与差异

```sh {1,2,3}
$ jj st                                                 # 查看工作区状态（缩写 status）
$ jj log                                                # 查看提交历史
$ jj diff                                               # 查看当前提交相对父提交的差异
$ jj log -n 10                                          # 查看最近 N 个提交
$ jj log -r ::                                          # 查看全部提交
$ jj log -p                                             # 查看历史并附带 diff
$ jj log README.md                                      # 查看指定文件的提交历史
$ jj diff -r <change-id>                                # 查看指定提交相对父提交的差异
$ jj diff --from main                                   # 比较 main 到当前工作区
$ jj diff --from <change-id> --to <change-id>           # 比较两个提交
$ jj show                                               # 查看当前提交的说明和 diff
```

## 开始工作与记录改动

```sh {1,4,5,6}
$ jj new                                                # 在当前提交之上新建空工作区提交
$ jj new main                                           # 基于 main 新建工作区提交
$ jj new -m "message"                                   # 新建工作区提交并添加说明
$ jj describe -m "message"                              # 为当前工作区提交添加说明（缩写 desc）
$ jj commit -m "message"                                # 添加说明并新建空工作区提交（缩写 ci）
$ jj squash                                             # 将当前改动合并到父提交
$ jj new main other                                     # 以多个提交为父提交，创建合并提交
$ jj edit <change-id>                                   # 将工作区切换到指定提交并继续修改
```

## 推送与同步

::tip
jj 没有 `git pull`。先执行 `jj git fetch`，再执行 `jj rebase -o main`。
::

```sh {1,2,3,5}
$ jj git fetch                                          # 从远程抓取更新
$ jj rebase -o main                                     # 将当前历史变基到 main 之上
$ jj git push                                           # 推送已跟踪的书签和标签
$ jj git push -c @-                                     # 按父提交 change ID 生成书签并推送
$ jj git push -b my-feature                             # 推送指定书签；未跟踪时自动跟踪
$ jj git push --named my-feature=@-                     # 以新书签名推送指定提交
$ jj git push --dry-run                                 # 预览远程引用的变更
```

## 书签 bookmark

::tip
书签对应 Git 分支，但不会随工作区自动前移，需要时使用 `create` / `set` / `move` 更新指针。
::

```sh {1,3,6,8}
$ jj bookmark list                                      # 列出书签（缩写 b l）
$ jj bookmark list -a                                   # 列出各远程上的书签
$ jj bookmark create my-feature -r @-                   # 在父提交上创建书签
$ jj bookmark set my-feature -r @                       # 创建书签，或将其指向当前提交（缩写 b s）
$ jj bookmark move my-feature --to @-                   # 移动已有书签；不可用于新建
$ jj bookmark track my-feature@origin                   # 跟踪远程书签
$ jj bookmark rename old-feature new-feature            # 重命名书签
$ jj bookmark delete my-feature                         # 删除本地书签，下次 push 会同步删除远程
```

按评审意见追加新提交：

```sh {1,3,4}
$ jj new my-feature                                     # 在书签上继续修改
$ jj commit -m "address pr comments"                    # 添加说明并新建空工作区提交
$ jj bookmark move my-feature --to @-                   # 将书签移动到新提交
$ jj git push -b my-feature                             # 推送指定书签
```

按评审意见改写已有提交后再推送（`my-feature-` 末尾的 `-` 表示该书签的父提交）：

```sh {1,2,3}
$ jj new my-feature-                                    # 在书签的父提交上开始修改
$ jj squash                                             # 将改动合并到待改写的提交
$ jj git push -b my-feature                             # 类似 force-with-lease；他人已基于旧提交时慎用
```

## 切换提交

::tip
在已使用 jj 的同一工作区中，避免再使用 `git switch` / `git commit` 切换分支或提交。
::

```sh {1,2}
$ jj new main                                           # 基于 main 开始新工作
$ jj new my-feature                                     # 基于指定书签继续修改
$ jj edit <change-id>                                   # 直接编辑已有提交
$ jj next                                               # 移动到后一个变更
$ jj prev                                               # 移动到前一个变更
```

## 改写与组合

```sh {1,2,5}
$ jj squash                                             # 将当前改动合并到父提交
$ jj squash -i                                          # 交互式选择要合并的部分
$ jj squash --into @--                                  # 将当前改动合并到祖父提交
$ jj split                                              # 将当前提交拆成两个
$ jj rebase -o main                                     # 变基到 main 之上
$ jj rebase -s <change-id> -o main                      # 变基指定提交及其子孙
$ jj rebase -r <change-id> -o main                      # 仅变基指定提交，将其子孙改挂到原父提交
```

## 回滚与撤销

::tip
优先使用 `jj undo`，可连续执行多次；使用 `jj redo` 恢复。查看操作历史使用 `jj op log`。
::

```sh {1,2,3,6}
$ jj undo                                               # 撤销上一次操作
$ jj redo                                               # 重做被 undo 撤销的操作
$ jj op log                                             # 查看操作历史
$ jj op restore <op-id>                                 # 恢复到指定操作之后的状态
$ jj restore <file>                                     # 将文件恢复为父提交中的内容
$ jj abandon <change-id>                                # 丢弃指定提交，指向它的书签默认也会被删除
$ jj revert -r <change-id> -o @                         # 在指定位置生成反向提交（保留原提交）
```

## 冲突

::tip
变基或合并遇到冲突时，操作会直接完成，冲突记录在提交中。没有 `git rebase --continue`。解决后使用 `jj squash` 合并回冲突提交。也可直接编辑冲突标记，再执行 `jj squash`。
::

```sh {1,2,3,6}
$ jj new <change-id>                                    # 在冲突提交之上新建工作区
$ jj new @                                              # 当前位于冲突提交时
$ jj resolve                                            # 使用合并工具逐个解决冲突
$ jj resolve -l                                         # 列出冲突文件
$ jj resolve --tool :editor                             # 在编辑器中修改冲突标记
$ jj squash                                             # 将解决方案合并回冲突提交
```

## 远程仓库

```sh {1,2,3}
$ jj git remote list                                    # 列出远程仓库
$ jj git remote add origin <url>                        # 添加远程仓库
$ jj git remote set-url origin <url>                    # 修改远程地址
$ jj git remote rename <old> <new>                      # 重命名远程
$ jj git remote remove <remote>                         # 移除远程（仅删除本地引用）
$ jj git root                                           # 输出底层 git 仓库路径
```

## 工作区 workspace

```sh {1,2}
$ jj workspace list                                     # 列出所有工作区
$ jj workspace add <path>                               # 新增工作区（类似 git worktree）
$ jj workspace remove <name>                            # 移除工作区
$ jj workspace root                                     # 输出当前工作区根目录
```

## 标签

```sh {1,2,3}
$ jj tag list                                           # 列出标签
$ jj tag set <tag> -r @-                                # 在指定提交上创建或更新标签
$ jj git push -t <tag>                                  # 推送指定标签
$ jj tag delete <tag>                                   # 删除本地标签，下次 push 会同步删除远程
```
